## 2. What you are building

A single-page app, mobile-first, dark, **sleek and minimalist**. Five views.

**Design direction — read this before writing any CSS.**

Minimalist here means *restraint*, not *emptiness*. Concretely:

- **Near-black background, one accent colour, nothing else.** No gradients, no drop
  shadows, no card borders. Separation comes from spacing and a single hairline rule.
- **Type carries the design.** Large, tight-tracked titles; small, muted metadata. The
  visual hierarchy is font size and opacity, not boxes and colour.
- **Times are the hero data.** Set them in tabular numerals so columns align down the page.
  This is the single most important typographic decision in the app.
- **System font stack, no web fonts.** The app is opened on the street on mobile data; a
  font request that blocks first paint is a worse sin than a generic typeface.
- **Whitespace is generous and consistent.** Use a 4px spacing scale. Never eyeball a
  margin.
- **Motion is minimal.** Countdown updates and view changes only. No entrance animations.
- **Chrome is invisible.** No headers that don't earn their height, no icon buttons where a
  word will do, no borders around anything that spacing can separate.

**Tech stack.** Vite, React 18, TypeScript, React Router, Vitest. Plain CSS with custom
properties — **no Tailwind, no component library, no CSS-in-JS**. The design is bespoke and
small; a framework would add config and constraint without saving work. Date handling uses
native `Intl.DateTimeFormat` with `timeZone: "Europe/Paris"` — no date library.

---

## 3. Global rules

- All timestamps in the JSON are **UTC with offset**. Never display a raw `start_utc`.
  Always format through `Europe/Paris`.
- The user's device clock is the source of "now". Do not trust `generated_at` for now.
- Never crash on missing data. `films` may be empty, `booking_url` may be null,
  `accessibility` may be null, a venue may have no screenings.
- TypeScript `strict: true`. No `any`.
- Commit after every task with a `feat:`, `fix:`, `test:` or `chore:` prefix.
- Run `npm run build` before committing any task that touches the frontend. A task is not
  done if the production build fails.

## Task 0: Fix two packaging faults

Two independent problems in `pyproject.toml`, both fixed in this one task.

**Fault 1 — `tzdata` is undeclared.** `cinepipeline/core/models.py` calls
`ZoneInfo("Europe/Paris")` at import time. On Linux this reads the system tz database.
**Windows has no system tz database**, so it needs the `tzdata` PyPI package. It is
currently in `.venv` by accident and is not declared, so a fresh `pip install -e .` on

configuration, setuptools uses flat-layout discovery, which treats any top-level directory

do not create it and `pip install -e .` still succeeds there. As soon as Task 1 commits
`web/package.json`, every CI checkout will contain `web/` — and `refresh.yml` runs

```ts
import type { Film, Payload, Screening, Venue } from "./types";

export async function loadPayload(): Promise<Payload> {
  // BASE_URL is "/paris-cinema/" on GitHub Pages and "/" in dev. An absolute
  // "/data/..." path would 404 on Pages, so always build from BASE_URL.
  const url = `${import.meta.env.BASE_URL}data/screenings.json`;
  const res = await fetch(url, { cache: "no-cache" });
  if (!res.ok) throw new Error(`Failed to load showtimes (HTTP ${res.status})`);
  return (await res.json()) as Payload;
}

/** Film lookup that never throws and never assumes `films` is populated. */
export function filmFor(payload: Payload, s: Screening): Film | null {
  if (!s.film_key) return null;
  return payload.films[s.film_key] ?? null;
}

/** Display title: English when TMDB matched, otherwise the marquee title. */
export function displayTitle(payload: Payload, s: Screening): string {
  return filmFor(payload, s)?.title_en || s.title_marquee;
}

/** Secondary title, shown only when it differs from the headline. */
export function secondaryTitle(payload: Payload, s: Screening): string | null {
  const en = filmFor(payload, s)?.title_en;
  return en && en !== s.title_marquee ? s.title_marquee : null;
}

export function posterUrl(film: Film | null, size: "w185" | "w500"): string | null {
  if (!film?.poster_path) return null;
  return `https://image.tmdb.org/t/p/${size}${film.poster_path}`;
}

export function venueMap(payload: Payload): Map<string, Venue> {
  return new Map(payload.venues.map((v) => [v.id, v]));
}
```

## Task 3: Time bucketing — the core logic, fully tested

This is the only genuinely tricky logic in the frontend, and the whole "starting soon"
feature rests on it. It is a pure function, so test it properly.

**Files created:** `web/src/time.ts`, `web/src/time.test.ts`

**Bucketing rules:**

| Bucket | Condition relative to `now` |
| --- | --- |
| `justStarted` | started between 15 minutes ago and now |
| `next30` | starts within the next 30 minutes |
| `withinHour` | starts in 30–60 minutes |
| `laterToday` | starts later than 60 minutes, same Paris calendar day |

A screening more than 15 minutes past its start time appears in no bucket.
**Chain venues are excluded from all four buckets** — they belong only to their own view.

```ts
import type { Screening, Venue } from "./types";

export const PARIS = "Europe/Paris";
export const GRACE_MINUTES = 15;

const hhmm = new Intl.DateTimeFormat("en-GB", {
  timeZone: PARIS, hour: "2-digit", minute: "2-digit", hour12: false,
});

const ymd = new Intl.DateTimeFormat("en-CA", {
  timeZone: PARIS, year: "numeric", month: "2-digit", day: "2-digit",
});

const dayLabelFmt = new Intl.DateTimeFormat("en-GB", {
  timeZone: PARIS, weekday: "short", day: "numeric", month: "short",
});

export function formatParisTime(iso: string): string {
  return hhmm.format(new Date(iso));
}

/** "2026-08-10" in Paris local terms. en-CA gives ISO-ordered output. */
export function parisDayKey(iso: string | Date): string {
  return ymd.format(typeof iso === "string" ? new Date(iso) : iso);
}

export function formatDayLabel(iso: string | Date): string {
  return dayLabelFmt.format(typeof iso === "string" ? new Date(iso) : iso);
}

export function minutesUntil(iso: string, now: Date): number {
  return Math.round((new Date(iso).getTime() - now.getTime()) / 60000);
}

/** "in 12 min" / "just started" / "20:15" */
export function countdownLabel(iso: string, now: Date): string {
  const m = minutesUntil(iso, now);
  if (m < 0) return "just started";
  if (m === 0) return "starting now";
  if (m < 60) return `in ${m} min`;
  return formatParisTime(iso);
}

export interface Buckets {
  justStarted: Screening[];
  next30: Screening[];
  withinHour: Screening[];
  laterToday: Screening[];
}

export function bucketScreenings(
  screenings: Screening[], venues: Venue[], now: Date
): Buckets {
  const independents = new Set(
    venues.filter((v) => v.kind === "independent").map((v) => v.id)
  );
  const today = parisDayKey(now);

  const out: Buckets = { justStarted: [], next30: [], withinHour: [], laterToday: [] };

  for (const s of screenings) {
    if (!independents.has(s.venue_id)) continue;
    const m = minutesUntil(s.start_utc, now);

    if (m < -GRACE_MINUTES) continue;
    if (m < 0) out.justStarted.push(s);
    else if (m <= 30) out.next30.push(s);
    else if (m <= 60) out.withinHour.push(s);
    else if (parisDayKey(s.start_utc) === today) out.laterToday.push(s);
  }

  const byStart = (a: Screening, b: Screening) => a.start_utc.localeCompare(b.start_utc);
  out.justStarted.sort(byStart);
  out.next30.sort(byStart);
  out.withinHour.sort(byStart);
  out.laterToday.sort(byStart);
  return out;
}

/** Groups screenings by Paris day key, ascending. */
export function groupByDay(screenings: Screening[]): Map<string, Screening[]> {
  const map = new Map<string, Screening[]>();
  for (const s of [...screenings].sort((a, b) => a.start_utc.localeCompare(b.start_utc))) {
    const k = parisDayKey(s.start_utc);
    const list = map.get(k);
    if (list) list.push(s);
    else map.set(k, [s]);
  }
  return new Map([...map.entries()].sort(([a], [b]) => a.localeCompare(b)));
}
```

```tsx
import { useMemo, useState } from "react";
import { Link } from "react-router-dom";
import type { Payload } from "../types";
import { formatParisTime, parisDayKey } from "../time";

export function CinemasView({ payload, now }: { payload: Payload; now: Date }) {
  const [query, setQuery] = useState("");

  const stats = useMemo(() => {
    const today = parisDayKey(now);
    const map = new Map<string, { today: number; next: string | null }>();
    for (const v of payload.venues) map.set(v.id, { today: 0, next: null });
    for (const s of [...payload.screenings].sort((a, b) =>
      a.start_utc.localeCompare(b.start_utc)
    )) {
      const e = map.get(s.venue_id);
      if (!e) continue;
      if (parisDayKey(s.start_utc) === today) e.today += 1;
      if (!e.next && new Date(s.start_utc) > now) e.next = s.start_utc;
    }
    return map;
  }, [payload, now]);

  const filtered = useMemo(() => {
    const q = query.trim().toLowerCase();
    const independents = payload.venues.filter((v) => v.kind === "independent");
    const matched = q
      ? independents.filter((v) => v.name.toLowerCase().includes(q))
      : independents;
    return matched.sort(
      (a, b) => a.arrondissement - b.arrondissement || a.name.localeCompare(b.name)
    );

  const groups = useMemo(() => {
    const m = new Map<number, typeof filtered>();
    for (const v of filtered) {
      const list = m.get(v.arrondissement);
      if (list) list.push(v);
      else m.set(v.arrondissement, [v]);
    }
    return [...m.entries()].sort(([a], [b]) => a - b);
  }, [filtered]);

  return (

        className="search"
        type="search"
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Search cinemas"
        aria-label="Search cinemas"
```

```tsx
import { useMemo, useState } from "react";
import type { Payload } from "../types";
import { venueMap } from "../data";
import { parisDayKey } from "../time";
import { ScreeningRow } from "../components/ScreeningRow";

export function ChainsView({ payload, now }: { payload: Payload; now: Date }) {
  const venues = useMemo(() => venueMap(payload), [payload]);

  const chains = useMemo(() => {
    const names = new Set(
      payload.venues.filter((v) => v.kind === "chain" && v.chain).map((v) => v.chain!)
    );
    return [...names].sort();
  }, [payload]);

  const [active, setActive] = useState<string | null>(null);
  const chain = active ?? chains[0] ?? null;

  const screenings = useMemo(() => {
    if (!chain) return [];
    const ids = new Set(
      payload.venues.filter((v) => v.chain === chain).map((v) => v.id)
    );
    const today = parisDayKey(now);
    return payload.screenings
      .filter(
        (s) =>
          ids.has(s.venue_id) &&
          parisDayKey(s.start_utc) === today &&
          new Date(s.start_utc) > now
      )
      .sort((a, b) => a.start_utc.localeCompare(b.start_utc));
  }, [payload, chain, now]);

  if (chains.length === 0) return <p className="empty">No chain venues in the data.</p>;

  return (
    <>
      <div className="daybar">
        {chains.map((c) => (
          <button
            key={c}
            onClick={() => setActive(c)}
            className={c === chain ? "day day-on" : "day"}
          >
            <span className="day-label">{c}</span>
          </button>
        ))}
      </div>

      <div className="section">
        {screenings.length === 0 ? (
          <p className="empty">Nothing left today at {chain}.</p>
        ) : (
          screenings.map((s) => (
            <ScreeningRow
              key={`${s.venue_id}-${s.start_utc}-${s.title_marquee}`}
              payload={payload}
              screening={s}
              venue={venues.get(s.venue_id)}
              now={now}
            />
          ))
        )}
      </div>
    </>
  );
}
```

## Task 10: Deploy to GitHub Pages

**Files modified:** `.github/workflows/refresh.yml`

- [ ] **Step 1:** Enable Pages with GitHub Actions as the source.

Go to **Settings -> Pages** on the repository. Under **Build and deployment -> Source**,
select **GitHub Actions**. Do *not* select "Deploy from a branch" — that is what is
currently serving `README.md`, and it will keep doing so until you change it.

- [ ] **Step 2:** Add the TMDB secret and the baseline variable.

| Name | Type | Value |
| --- | --- | --- |
| `TMDB_API_KEY` | Secret | Your TMDB **v3** API key (32-char hex, not the JWT) |
| `BASELINE_URL` | Variable | `https://denizdurbin.github.io/paris-cinema/data/screenings.json` |

Secrets: **Settings -> Secrets and variables -> Actions -> Secrets**.
Variables: the **Variables** tab beside it. `BASELINE_URL` is deliberately a variable, not
a secret — it is a public URL and you want to be able to read it back.

No token is needed. Pages deploys authenticate with the workflow's own OIDC identity.

- [ ] **Step 3:** Add the SPA fallback to `web/package.json`.

GitHub Pages serves static files with no rewrite rules, so a deep link like
`/paris-cinema/cinemas` looks for a file that does not exist and 404s. The standard fix is
to ship a copy of `index.html` as `404.html`: Pages serves it for any unmatched path, the
app boots, and React Router resolves the URL client-side.

Change the `build` script so the copy happens on every build:

```json
"scripts": {
  "dev": "vite",
  "build": "tsc -b && vite build && node -e \"require('fs').copyFileSync('dist/index.html','dist/404.html')\"",
  "preview": "vite preview",
  "test": "vitest run"
}
```

- [ ] **Step 4:** Replace `.github/workflows/refresh.yml` entirely.

```yaml
name: refresh
on:
  schedule:
    - cron: '5 7-21 * * *'
  workflow_dispatch:
  push:
    branches: [master]

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5

      - uses: actions/setup-python@v6
        with:
          python-version: '3.13'
      - run: pip install -e .
      - run: python -m cinepipeline
        env:
          TMDB_API_KEY: ${{ secrets.TMDB_API_KEY }}
          BASELINE_URL: ${{ vars.BASELINE_URL }}

      - uses: actions/setup-node@v5
        with:
          node-version: '22'
      - run: npm ci
        working-directory: web
      - run: npm run build
        working-directory: web

      - uses: actions/upload-pages-artifact@v3
        with:
          path: web/dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Four things here that are easy to get wrong:

- **The pipeline runs before the Vite build.** Vite copies `web/public/` into `web/dist/`
  at build time, so reversing the order ships yesterday's data.
- **`permissions` is mandatory.** Without `pages: write` and `id-token: write` the deploy
  step fails with a permissions error that does not name the missing scope.
- **`concurrency.group` must be `pages`.** Two Pages deploys running at once will have one
  of them fail.
- **Build and deploy are separate jobs.** `deploy-pages` requires it; it consumes the
  artifact the build job uploaded.

If any action reports a Node deprecation warning, bump its major version. These warnings do
not fail the run — the runner substitutes a newer Node — so treat them as tidying, not
breakage.

## If something breaks

| Symptom | Cause |
| --- | --- |
| All times look wrong by 1–2 hours | Something formatted `start_utc` without `timeZone: "Europe/Paris"` |
| No posters anywhere | `TMDB_API_KEY` is unset — expected, not a bug |
| `/cinemas` 404s on refresh | `404.html` copy missing from the build script |
| Every asset 404s once deployed | Vite `base` does not match the Pages subpath |
| Routes blank on Pages but fine in dev | Router `basename` missing or mismatched |

| Site still shows the README | Pages source is still "Deploy from a branch", not "GitHub Actions" |
| Deployed data is stale by a day | Vite build ran before the Python pipeline |
| Tests show UTC times | Node built without full ICU |
